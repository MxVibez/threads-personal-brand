# Максим: Threads Content Workspace

## Цель

Создать личную систему Максима для привлечения клиентов из Threads на разработку Telegram Mini Apps, приложений для мессенджеров, веб-, iOS- и Android-продуктов, а также на производство AI-аватаров и AI-блогеров для брендов.

Главный результат — не поток постов сам по себе, а измеримый маршрут: полезная публикация → ответ с кодовым словом или переход в Telegram → разбор задачи → квалифицированная заявка. Система автоматически публикует только заранее одобренные материалы; генерация без контроля пока не включается.

## Границы изоляции

- Исходный клиентский проект используется только для чтения и не изменяется.
- Не переносятся `.git`, `.env`, токены, секреты, базы данных, Docker volumes, `node_modules`, `dist`, build-артефакты и клиентские изображения.
- Не переносятся имя, аватар, персональные данные, нишевые тексты, поисковые запросы, seed-данные и исходные рыночные данные клиента.
- Новый проект не обращается к сервисам, аккаунтам, базам, хостам или данным клиентского проекта.
- Новая директория получает собственную Git-историю.

## MVP

1. Telegram Mini App Максима с очередью материалов и жестами одобрения/отклонения.
2. Серверная проверка Telegram Mini App `initData` и allowlist владельцев.
3. Черновики, версии, решения, план публикаций и журнал событий в PostgreSQL.
4. Идемпотентная очередь публикаций через Redis/BullMQ.
5. Dry-run publisher по умолчанию и отдельный worker.
6. Стартовый голос Максима: прямой, спокойный, предметный, без недоказанных обещаний и технического перегруза.
7. Контентные направления: приложения как путь к продаже, Telegram Mini Apps, веб/mobile-продукты, AI-аватары и AI-блогеры.
8. CTA через кодовые слова `РАЗБОР`, `АВАТАР`, `ПЕРСОНАЖ`; фактическая атрибуция заявок остаётся следующим этапом.

## Пользовательский путь

1. Система собирает разрешённые публичные сигналы по выбранным темам или получает идею вручную.
2. Материал появляется в Mini App с тезисом, целью, риском и источниками.
3. Максим отклоняет материал либо одобряет и выбирает время.
4. Worker автоматически публикует одобренный материал через официальный Threads API.
5. Читатель отвечает кодовым словом или переходит в Telegram по ссылке профиля.
6. Максим проводит разбор и квалифицирует задачу: приложение, AI-аватар или AI-персонаж.

Критерий успеха MVP: не охват сам по себе, а число содержательных диалогов и квалифицированных заявок с понятным источником публикации.

## Архитектура

- `miniapp/`: React + TypeScript + Vite, мобильный интерфейс Telegram Mini App.
- `src/`: модульный монолит NestJS с Fastify adapter.
- `src/domain/`: бизнес-инварианты черновиков и публикаций.
- `src/infrastructure/database/`: PostgreSQL repositories и версионируемые миграции.
- `src/infrastructure/queue/`: Redis/BullMQ и идемпотентные задания.
- `src/worker/`: обработка и восстановление публикаций.
- `docker-compose.yml`: локальные PostgreSQL, Redis, API, worker и Mini App; без внешнего deployment-контура.

Главный компромисс: структура намеренно сохраняет Redis/worker и полноценную БД, хотя для простого прототипа это тяжелее in-memory варианта. Это оправдано задачей сохранить проверенный каркас продолжительных операций и безопасных повторов.

## Данные

- Локальная БД начинается пустой после миграций.
- Демонстрационная запись создаётся только явным локальным действием и содержит стартовый материал о продуктовой воронке Максима.
- Реальные пользовательские, рыночные и клиентские данные в репозиторий не включаются.
- Публичные материалы внешних платформ считаются недоверенным вводом; фактический сбор данных на этом этапе отключён.

## Секреты и интеграции

Все привилегированные значения существуют только в server runtime environment и перечислены без значений в `.env.example`:

- отдельный `TELEGRAM_BOT_TOKEN`;
- `META_THREADS_APP_ID` и `META_THREADS_APP_SECRET`;
- `THREADS_USER_ID` и `THREADS_ACCESS_TOKEN`;
- `APIFY_API_TOKEN` и webhook secret;
- `OPENAI_API_KEY`;
- пароли PostgreSQL и служебные encryption/webhook secrets.

Во frontend запрещены provider bearer-токены, bot token, пароли и refresh tokens. `THREADS_DRY_RUN=true` и внешние сборщики выключены по умолчанию.
